# Работа с Git и GitHub

Памятка по типовым действиям с проектом — практическая часть лабораторной работы № 20.

## 1. Репозиторий

**Репозиторий** — хранилище проекта вместе со всей историей изменений. Оно состоит из рабочей области (файлы на диске) и хранилища (папка `.git`, где лежат коммиты).

```bash
git init -b main                         # создать локальный репозиторий
git clone <url>                          # скопировать существующий репозиторий
git remote add origin <url>              # привязать удалённый репозиторий
```

## 2. Коммит

**Коммит** — зафиксированное состояние проекта с уникальным хешем, автором, датой и сообщением.

```bash
git status                               # какие файлы изменены
git add <файл>                           # подготовить изменения
git commit -m "Краткое описание"         # создать коммит
git log --oneline --graph --decorate     # история коммитов
```

## 3. Ветка (branch) и мастер (main)

**Ветка** — отдельная линия разработки. Основная ветка называется `main` (раньше — `master`). Ветки позволяют делать изменения, не затрагивая стабильную версию.

```bash
git branch feature/docs                  # создать ветку
git switch feature/docs                  # переключиться на неё
git switch -c feature/docs               # создать и сразу переключиться
git branch -a                            # список веток
```

## 4. Пуш (push)

**Пуш** — отправка локальных коммитов в удалённый репозиторий на GitHub.

```bash
git push -u origin main                  # первый пуш
git push                                 # последующие пушы
```

## 5. Пул (pull)

**Пул** — получение изменений из удалённого репозитория и их слияние с локальной веткой.

```bash
git pull origin main                     # получить и слить изменения
git pull --rebase origin main            # получить и «переписать» свои коммиты поверх
```

## 6. Пулреквест (Pull Request, PR)

**Пулреквест** — предложение влить изменения из одной ветки в другую. В PR видно diff, историю коммитов, обсуждение и результаты проверок. Создаётся на сайте GitHub: **Compare & pull request → Create pull request**.

## 7. Мердж (merge)

**Мердж** — слияние веток.

```bash
git switch main
git merge feature/docs                   # слить ветку в main
```

На GitHub кнопка **Merge pull request** выполняет то же самое на сервере.

## 8. Кодревью (code review)

**Кодревью** — проверка изменений другим разработчиком до слияния. В GitHub review оставляют на вкладке **Files changed**: можно прокомментировать конкретную строку, одобрить изменения (**Approve**) или запросить правки (**Request changes**).

## 9. Форк (fork)

**Форк** — личная копия чужого репозитория в своём аккаунте. Нужен, чтобы предлагать изменения в проект, не имея прав на запись в оригинал: форк → правки в своей копии → Pull Request в оригинальный репозиторий.

## 10. Типовой рабочий цикл

```text
1. git switch main && git pull          # актуализировать основную ветку
2. git switch -c feature/<задача>       # создать ветку под задачу
3. правим файлы
4. git add . && git commit -m "..."     # закоммитить изменения
5. git push -u origin feature/<задача>  # отправить ветку на GitHub
6. открыть Pull Request
7. пройти кодревью и исправить замечания
8. выполнить Merge pull request
9. git switch main && git pull          # забрать результат к себе
```
